## 1. Product Summary

`auth-switch` is a local desktop app that lets users maintain multiple OpenAI Codex
accounts and switch between them in one click. It stores imported `auth.json` files in
a local SQLite database, replaces `~/.codex/auth.json` when switching, and exposes a
system tray/menu-bar menu for quick access.

**Core constraints:**
- Local only — no network calls, no telemetry.
- Codex path only — `${CODEX_HOME:-$HOME/.codex}/auth.json`. Not configurable.
- No encryption — relies on file-system permissions.
- Close window ≠ quit — app stays resident in the tray after window close.

## 4. Database Schema

Database file location:

```
~/.auth-switch/auth-switch.db
```

### 4.1 Table: `accounts`

```sql
CREATE TABLE IF NOT EXISTS accounts (
  id          TEXT    PRIMARY KEY,          -- randomUUID()
  name        TEXT    NOT NULL,             -- user-visible name; defaults to email or "Unnamed account"
  email       TEXT,                         -- parsed from auth.json; may be null
  auth_json   TEXT    NOT NULL,             -- complete auth.json content as JSON string
  auth_hash   TEXT    NOT NULL,             -- SHA-256 of auth_json; used for duplicate detection
  is_current  INTEGER NOT NULL DEFAULT 0,   -- 1 = currently active account
  created_at  INTEGER NOT NULL,             -- Unix timestamp (ms)
  updated_at  INTEGER NOT NULL,             -- Unix timestamp (ms)
  last_used_at INTEGER                      -- Unix timestamp (ms); set on each switch
);
```

### 4.2 Table: `settings`

```sql
CREATE TABLE IF NOT EXISTS settings (
  key   TEXT PRIMARY KEY,
  value TEXT
);
```

Keys used in MVP:

| Key | Type | Description |
|---|---|---|
| `first_run_done` | `"1"` | Set after first-run dialog has been dismissed |
| `launch_at_login` | `"1"` / `"0"` | Auto-launch preference (phase 2) |

### 4.3 Migrations

Schema version stored in SQLite `PRAGMA user_version`.

- Version 0 → 1: create `accounts` and `settings` tables.

Migration runner reads `PRAGMA user_version`, applies pending migrations
in order, then sets the new version. All migrations run inside a transaction.

## 5. Codex Auth Path Resolution

```ts
// src/main/codex/paths.ts

import os from "os";
import path from "path";

export function getCodexAuthPath(): string {
  const base = process.env.CODEX_HOME ?? path.join(os.homedir(), ".codex");
  return path.join(base, "auth.json");
}

export function getCodexDir(): string {
  return path.dirname(getCodexAuthPath());
}
```

On Windows `os.homedir()` returns the real user profile directory
(`C:\Users\Alice`), not the `HOME` environment variable, which may differ
when Git for Windows or MSYS is installed.

## 6. Email Parsing

```ts
// src/main/codex/parser.ts

export function parseEmail(raw: unknown): string | null {
  if (typeof raw !== "object" || raw === null) return null;
  const obj = raw as Record<string, unknown>;

  // Candidates in priority order
  const candidates: Array<() => string | null> = [
    () => str(obj.email),
    () => str((obj.account as Record<string, unknown>)?.email),
    () => str((obj.user as Record<string, unknown>)?.email),
    () => str((obj.profile as Record<string, unknown>)?.email),
    () => decodeJwtEmail(obj.tokens),
  ];

  for (const fn of candidates) {
    const v = fn();
    if (v) return v;
  }
  return null;
}

function str(v: unknown): string | null {
  return typeof v === "string" && v.trim() ? v.trim() : null;
}

function decodeJwtEmail(tokens: unknown): string | null {
  if (typeof tokens !== "object" || tokens === null) return null;
  const t = tokens as Record<string, unknown>;
  const idToken = str(t.id_token);
  if (!idToken) return null;
  try {
    const parts = idToken.split(".");
    if (parts.length < 2) return null;
    const payload = JSON.parse(Buffer.from(parts[1], "base64url").toString());
    return str(payload.email);
  } catch {
    return null;
  }
}
```

## 7. Atomic File Writer

```ts
// src/main/codex/writer.ts

import fs from "fs";
import path from "path";

export function atomicWrite(targetPath: string, content: string): void {
  const dir = path.dirname(targetPath);
  fs.mkdirSync(dir, { recursive: true });

  const tmp = `${targetPath}.tmp.${Date.now()}`;
  fs.writeFileSync(tmp, content, { encoding: "utf-8" });

  if (process.platform === "win32" && fs.existsSync(targetPath)) {
    fs.unlinkSync(targetPath);  // Windows rename fails if target exists
  }
  fs.renameSync(tmp, targetPath);
}
```

```ts
// src/main/db/accounts.ts

export interface AccountRow {
  id: string;
  name: string;

  auth_json: string;
  auth_hash: string;

// Methods on the Database class:
// getAll():           AccountRow[]        — ordered by created_at ASC
// getById(id):        AccountRow | null
// getCurrent():       AccountRow | null
// insert(row):        void
// updateMeta(id, { name, email }): void
// updateAuthJson(id, auth_json, auth_hash, updated_at): void

// delete(id):         void
// hashExists(hash):   boolean            — for duplicate detection
```

`setCurrent(id)` runs as a transaction:

```sql
UPDATE accounts SET is_current = 0;
UPDATE accounts SET is_current = 1, last_used_at = ? WHERE id = ?;
```

## 9. Switch Logic

This is the core of the app. It lives in `src/main/ipc.ts` (called from the
`switch-account` IPC handler) and implements the **backfill-then-replace** pattern.

```
switchAccount(targetId: string): SwitchResult

1. Load target account from DB → error if not found.
2. Load current account from DB (getCurrent).
3. If current account exists and current account id ≠ targetId:
     a. Read ~/.codex/auth.json from disk (may not exist if deleted externally).
     b. If file exists and is valid JSON:
          - Compute new hash.
          - Update current account's auth_json, auth_hash, updated_at in DB.
            (This preserves token refreshes that Codex wrote since last switch.)
4. Ensure ~/.codex/ directory exists.
5. Atomic-write target.auth_json → ~/.codex/auth.json.
6. DB: setCurrent(targetId)  — transaction, clears others, sets target.
7. Send tray rebuild signal.
8. Emit "accounts-changed" event to renderer window.
9. Fire system notification: "Switched to <name>".
10. Return { success: true, account: target }.
```

Edge cases:

- **Step 3 read fails** (file missing or corrupted): skip backfill silently; log
  warning. Continue to step 4 — we still switch forward.
- **Step 5 write fails**: surface error to renderer; do not update DB.
- **Already current**: return early with `{ success: true, alreadyCurrent: true }`.

## 15. Import Flow

1. User clicks **[+ Add auth.json]** (main window) or **Add auth.json...** (tray).
2. Native file dialog opens — filter: `*.json`, any file.
3. Read file content.
4. Validate: must be valid JSON object.
5. Compute `SHA-256(content)`.
6. Check `hashExists(hash)`:
   - Yes → show: *"This auth.json is already in auth-switch."* → abort.
7. Parse email.
8. Check if another account has the same email (but different hash):
   - Yes → inform user with a note, allow continuing.
9. Show import confirmation dialog:
   - Name field (prefilled with email, or `"Unnamed account"`).
   - Confirm / Cancel.
10. Insert into DB:
    - `is_current = 0` (never auto-activate on import — user must explicitly switch).
11. Emit `accounts-changed`.
12. If this is the **first** account ever added: offer to set as current.

## 16. Delete Account Rules

- Cannot delete the current account directly.
- If user tries to delete the current account: show:
  *"Switch to another account before deleting this one."*
- On delete (non-current): simple confirmation dialog → `DELETE FROM accounts WHERE id = ?`.
- Deleting an account does **not** touch `~/.codex/auth.json`.
- Emit `accounts-changed`.

## 21. Security Notes

- `auth.json` contains OAuth access tokens and refresh tokens.
  Treat the database file (`~/.auth-switch/auth-switch.db`) as a credential store.
- The database must not be committed to version control (covered by `.gitignore`).
- The renderer runs with `contextIsolation: true`, `nodeIntegration: false`,
  and `sandbox: true`. All Node.js access goes through the preload bridge.
- No external network calls are made anywhere in the app.

---

## 22. Out of Scope for MVP

The following are intentionally deferred:

- Auto-launch at login
- Database/account export & import for backup
- Multi-language (i18n)
- Auto-updater
- Encryption of the SQLite database
- Custom Codex path override
- Support for any tool other than Codex
- Cloud sync
- Usage quota display
