## Background

MVP 实现已完成（账户管理、托盘快切、API profile、i18n）。
本计划针对 native-feel 审查暴露的 10 类问题，按优先级拆成可独立合并的 Phase，每个 Phase 都有明确的改动文件列表、成功标准和关键代码。

保持现有技术栈（Electron + React），不做原生 Shell 重写。目标是"更像桌面工具"的 Electron，而非 Raycast 级原生架构。

## Phase 1 — 单实例保护（优先级：P0 — 数据安全）

**问题**  
无 `app.requestSingleInstanceLock()`。双击两次可启动两个进程同时写 SQLite 和 `~/.codex/auth.json`，造成数据损坏，同时托盘出现两个图标。

**改动文件**  
- `src/main/index.ts`

**实现要点**

```ts
// src/main/index.ts 顶部，app.whenReady() 之前

const gotLock = app.requestSingleInstanceLock();
if (!gotLock) {
  app.quit();
} else {
  app.on("second-instance", () => {
    // 第二个实例启动时，聚焦已有主窗口
    showMainWindow();
  });

  app.whenReady().then(() => {
    // ... 现有初始化逻辑
  });
}
```

**成功标准**
- 打开两个终端同时运行 `pnpm dev`（或双击打包版），第二个进程立刻退出。
- 托盘图标始终只有一个。
- 第二个实例触发时，主窗口弹到前台。

    },
    {
      label: "Edit",
      submenu: [
        { role: "undo" },
        { role: "redo" },
        { type: "separator" },
        { role: "cut" },

## Phase 3 — 托盘点击行为（优先级：P1 — Windows 原生预期）

**问题**  
Windows 用户期待单击/双击托盘图标打开主窗口；当前只有右键菜单。macOS 虽然 click 弹菜单是惯例，但双击保底也更好。

**改动文件**  
- `src/main/tray.ts`

**实现要点**

```ts
// src/main/tray.ts — createTray() 中 tray 创建后
tray = new Tray(icon);
tray.setToolTip("auth-switch");

if (process.platform === "win32") {
  // Windows：单击打开主窗口
  tray.on("click", () => showMainWindow());
  tray.on("double-click", () => showMainWindow());
} else {
  // macOS：点击弹出菜单（Electron 默认行为），双击保底打开主窗口
  tray.on("double-click", () => showMainWindow());
}

rebuildTrayMenu();
```

**注意**：macOS 上 `tray.on("click")` 如果同时设置了 context menu，会阻止菜单弹出，因此 macOS 只绑定 `double-click`。

**成功标准**  
- Windows：单击托盘图标 → 主窗口出现。
- macOS：单击托盘图标 → 菜单弹出；双击 → 主窗口出现。

## Phase 4 — DOM 弹窗无障碍与键盘行为（优先级：P1 — 键盘/辅助功能）

**实现要点 — Focus Trap Hook**

```ts
// src/renderer/hooks/useFocusTrap.ts
import { useEffect, useRef } from "react";

const FOCUSABLE = [
  "a[href]",
  "button:not([disabled])",
  "input:not([disabled])",
  "select:not([disabled])",
  "textarea:not([disabled])",
  '[tabindex]:not([tabindex="-1"])',
].join(", ");

export function useFocusTrap(active: boolean) {
  const containerRef = useRef<HTMLElement | null>(null);

  useEffect(() => {
    if (!active) return;
    const container = containerRef.current;
    if (!container) return;

    // 保存触发元素以便恢复
    const previousFocus = document.activeElement as HTMLElement | null;

    // 焦点跳入
    const first = container.querySelector<HTMLElement>(FOCUSABLE);
    first?.focus();

    function handleKeyDown(event: KeyboardEvent): void {
      if (event.key !== "Tab") return;
      const focusable = Array.from(container!.querySelectorAll<HTMLElement>(FOCUSABLE));
      if (focusable.length === 0) return;

      const first = focusable[0];
      const last = focusable[focusable.length - 1];

      if (event.shiftKey) {
        if (document.activeElement === first) {
          event.preventDefault();
          last.focus();
        }
      } else {
        if (document.activeElement === last) {
          event.preventDefault();
          first.focus();
        }
      }
    }

    document.addEventListener("keydown", handleKeyDown);

    return () => {
      document.removeEventListener("keydown", handleKeyDown);
      previousFocus?.focus(); // 关闭时恢复焦点
    };
  }, [active]);

  return containerRef;
}
```

**实现要点 — ConfirmDialog 改造示例**

```tsx
// src/renderer/components/ConfirmDialog.tsx
import { useEffect } from "react";
import { useFocusTrap } from "../hooks/useFocusTrap";

export function ConfirmDialog({ ..., onCancel, onConfirm }) {
  const containerRef = useFocusTrap(true);

  // Escape 关闭
  useEffect(() => {
    function onKeyDown(event: KeyboardEvent) {
      if (event.key === "Escape") onCancel();
    }
    document.addEventListener("keydown", onKeyDown);
    return () => document.removeEventListener("keydown", onKeyDown);
  }, [onCancel]);

  return (
    <div
      role="dialog"
      aria-modal="true"
      aria-labelledby="confirm-title"
      ref={containerRef as React.RefObject<HTMLDivElement>}
      className="fixed inset-0 z-50 flex items-center justify-center bg-black/70 p-5"
    >
      <section className="...">
        <h2 id="confirm-title" className="...">{title}</h2>
        {/* ... */}
      </section>
    </div>
  );
}
```

- `ref={containerRef}`。
- `useEffect` 绑定 `Escape` → `onCancel()`。

## Phase 6 — 窗口尺寸可调与位置记忆（优先级：P2 — 体验质量）

**问题**  
`resizable: false`，固定 520×600，可能在高缩放比例 Windows 或中文长文本下截断。窗口位置不记忆，每次重新打开到默认位置。

**改动文件**  
- `src/main/window.ts`
- `src/main/db/settings.ts` — 添加窗口尺寸/位置的读写帮助函数
- `src/renderer/index.css` — 移除 `min-height: 600px`（可改为较小的下限）

**实现要点**

```ts
// src/main/db/settings.ts — 补充工具函数
interface WindowBounds {
  x?: number;
  y?: number;
  width: number;
  height: number;
}

export function getWindowBounds(): WindowBounds {
  const raw = getStringSetting("window_bounds");
  if (!raw) return { width: 520, height: 640 };
  try {
    return JSON.parse(raw) as WindowBounds;
  } catch {
    return { width: 520, height: 640 };
  }
}

export function setWindowBounds(bounds: WindowBounds): void {
  setStringSetting("window_bounds", JSON.stringify(bounds));
}
```

```ts
// src/main/window.ts — 创建时读取 bounds
import { getWindowBounds, setWindowBounds } from "./db/settings";
import { screen } from "electron";

export function createMainWindow(): BrowserWindow {
  const saved = getWindowBounds();

  // 确保 bounds 在当前可见屏幕内
  let { x, y } = saved;
  const displays = screen.getAllDisplays();
  const visible = displays.some((d) => {
    const b = d.bounds;
    return (x ?? 0) >= b.x && (x ?? 0) < b.x + b.width
        && (y ?? 0) >= b.y && (y ?? 0) < b.y + b.height;
  });
  if (!visible) { x = undefined; y = undefined; }

  mainWindow = new BrowserWindow({
    width: saved.width,
    height: saved.height,
    x,
    y,
    minWidth: 480,
    minHeight: 520,
    resizable: true,          // ← 改为可调整
    // ...
  });

  // 关闭/隐藏前保存位置
  mainWindow.on("close", () => {
    if (mainWindow && !mainWindow.isDestroyed()) {
      setWindowBounds(mainWindow.getBounds());
    }
  });
}
```

**注意**：`settings` 表需要支持字符串值，检查现有 `getStringSetting`/`setStringSetting` 是否已存在；若无，仿照 `getBooleanSetting` 添加。

**成功标准**  
- 拖动调整窗口大小，关闭再打开，窗口恢复到上次尺寸和位置。
- 窗口最小尺寸不小于 480×520。
- 外接显示器断开后，窗口恢复到主屏可见区域内。
- `pnpm run typecheck` 通过。

## Phase 7 — 系统主题跟随（优先级：P2 — 外观一致性）

**问题**  
强制暗色，不跟随系统 light/dark 模式。使用 `color-scheme: dark` 全局锁定，忽略 `prefers-color-scheme`。

**产品权衡**  
当前 console 黑色风格是品牌选择，可以保留暗色作为默认，但建议至少正确设置 `nativeTheme.themeSource`，并在系统切换时同步。如果产品决定永远暗色，仍需做：
1. `nativeTheme.themeSource = "dark"` 显式声明，而非"未设置"。
2. 防止 WebView 初始化闪白。

若想完整支持 light 模式（未来可选）：
- CSS 改用 `prefers-color-scheme` 媒体查询 + CSS 变量。
- main 进程监听 `nativeTheme.on("updated")` → 向 renderer 推送主题。

**改动文件（最小路径，只修暗色声明）**

**改动文件（可选，完整 light/dark 支持）**

**成功标准（最小路径）**

## Phase 8 — 启动行为优化（优先级：P2 — 工具感）

**问题**  
每次启动都立刻打开主窗口，不符合"托盘工具"习惯。已有账户的情况下，用户更希望 app 安静驻留托盘，需要时再召唤。

**改动文件**  
- `src/main/index.ts`

**实现要点**

```ts
// src/main/index.ts
import { getBooleanSetting } from "./db/settings";

app.whenReady().then(() => {
  nativeTheme.themeSource = "dark";
  buildAppMenu();
  initDatabase();
  registerIpc();
  createTray();

  const hasAccounts = /* 检查是否有账户 */ (() => {
    const { listAccounts } = require("./services/accountsService");
    return (listAccounts() as unknown[]).length > 0;
  })();

  const firstRunDone = getBooleanSetting("first_run_done");

  // 有账户且已完成首次引导 → 安静驻留托盘，不打开窗口
  // 首次运行或无账户 → 打开主窗口
  if (!firstRunDone || !hasAccounts) {
    createMainWindow();
  }

  app.on("activate", () => {
    // macOS Dock 点击 / Spotlight 激活
    showMainWindow();
  });
});
```

**注意**：需确保 `first_run_done` 在 FirstRunDialog 完成后 + 账户导入后正确写入，这在现有逻辑中已有 `dismissFirstRun` IPC，应已覆盖。

**成功标准**  
- 第一次启动（无账户/未完成首次引导）：主窗口自动出现。
- 后续重启（已有账户）：主窗口不自动出现，托盘图标出现。
- macOS Dock 点击或 `activate` 事件触发主窗口显示。
- 托盘图标始终存在。

## Phase 10 — 平台 Material / Vibrancy（优先级：P3 — 可选视觉加分）

**问题**  
当前窗口背景是纯色 `#080b0f`，不使用平台 vibrancy/mica。对于 Electron 来说这是一定程度可以折中的地方，但加了以后质感提升明显。

**权衡**  
- macOS `vibrancy` 需要窗口 `transparent: true`，会影响现有 TailwindCSS 背景色使用方式。
- Windows `backgroundMaterial: "mica"` 需要 Electron >= 30 + Windows 11。
- 两者都需要一定调整，且跨平台效果差异大。
- **建议**：先做 macOS vibrancy，Windows 暂缓，保持纯色背景。

**改动文件（macOS vibrancy，可选）**  
- `src/main/window.ts`
- `src/renderer/index.css`

```ts
// src/main/window.ts — BrowserWindow 选项
mainWindow = new BrowserWindow({
  // ...
  transparent: process.platform === "darwin",
  vibrancy: process.platform === "darwin" ? "under-window" : undefined,
  visualEffectState: process.platform === "darwin" ? "active" : undefined,
  backgroundColor: process.platform === "darwin" ? "#00000000" : "#080b0f",
  // ...
});
```

```css
/* src/renderer/index.css — 仅 macOS 背景透明 */
body {
  /* 去掉纯色 #080b0f，改为半透明叠加 */
  background: radial-gradient(circle at top left, rgba(126, 231, 135, 0.08), transparent 28rem),
              rgba(8, 11, 15, 0.85);  /* ← 半透明，下层 vibrancy 透过来 */
}
```

**注意**：transparent 窗口拖动区域需要 `-webkit-app-region: drag` 在标题栏 div 上显式设置；否则无法拖动窗口。

```tsx
/* src/renderer/App.tsx — header 元素 */
<header
  style={{ WebkitAppRegion: "drag" } as React.CSSProperties}
  className="flex shrink-0 items-center justify-between border-b border-console-line px-5 py-4"
>
  {/* 按钮等可交互元素需要反设为 no-drag */}
  <div style={{ WebkitAppRegion: "no-drag" } as React.CSSProperties}>
    {/* language toggle, lock icon */}
  </div>
</header>
```

**成功标准**  
- macOS 上窗口背景可见毛玻璃效果。
- 拖动标题栏区域可移动窗口，按钮不触发拖动。
- Windows 上无视觉异常（`transparent: false`，纯色背景）。
- `pnpm run build` 通过。

## 不在本计划范围内

- 系统 accent color 跟随（需要 main 进程读取系统 accent，renderer CSS variable 动态更新；收益有限，暗色 console 风格下感知不明显）。
- Light theme 完整设计（需重新设计颜色系统，工作量较大，建议单独 issue）。
- Swift/AppKit + WebView2 原生 Shell 重写（不符合当前项目技术栈决策）。
- 自动更新（Sparkle / MSIX）（已在 MVP 计划中列为后续工作）。
- 崩溃报告 / Sentry 集成（同上）。
